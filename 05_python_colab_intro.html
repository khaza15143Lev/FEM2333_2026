1. Python & Google Colab

Corresponding notebook cells: Section 0 (Setup & smoke test).

1.1 What is Python, and why engineers use it

Python is a general-purpose programming language that reads almost like plain English. It has become the default language for engineering and scientific computing because a small set of add-on libraries turn it into a full replacement for a scientific calculator, a spreadsheet, and a plotting program at once:

numpy vectors, matrices, linear algebra   scipy numerical integration, root-finding, curve fitting   sympy symbolic algebra & calculus (exact, not numeric)   matplotlib plots and figures

Every one of these is used later in this guide, and every one of them ships pre-installed in Google Colab — there is nothing to download.

1.2 What is Google Colab

Definition. Google Colab is a free, browser-based version of a Jupyter notebook: a document that mixes formatted text (like this page) with blocks of Python code that you can run, edit, and re-run in place. Colab runs the code on a computer in the cloud, so you don't install Python on your own machine — you just need a Google account.
▶ Open Google Colab

1.3 Notebooks are made of cells

A notebook is a sequence of cells. There are two kinds:

  • Text (Markdown) cells — explanations, headings, and equations, like the paragraph you're reading now.
  • Code cells — actual Python. Click a code cell and press Shift + Enter (or the ▶ button on its left edge) to run it. The result appears directly underneath.
Try it. In a new code cell, type the line below and run it: 
print("Hello, CEE 2333")

Output

Hello, CEE 2333

print() is a Python function: it displays whatever is inside its parentheses. Anything after a # on a line is a comment — Python ignores it, but it's how you leave notes for yourself and your reader:

# This line does nothing when run — it's a note for humans
print("Comments start with a #")
Cells share memory, in order. A variable created in one code cell is still available in every cell below it, as long as that earlier cell has been run. If your results look wrong or a variable is "not defined," the usual fix is Runtime → Run all, so every cell executes in order from the top.

Section 02

2. Python Crash Course

Corresponding notebook cells: Section 1 (Python Basics).

This is the minimum vocabulary you need before touching engineering libraries. It takes about fifteen minutes to read and covers everything the rest of this guide relies on.

2.1 Variables & basic types

A variable is a name that stores a value. Python figures out the type automatically — you never declare it:

a = 12          # int (whole number)
E = 200e9       # float (200 × 10^9 — a Young's modulus, in Pa)
label = "node1" # str (text, in quotes)
is_fixed = True # bool (True / False)

Ordinary arithmetic works as you'd expect, with one Python-specific symbol to note:

OperatorMeaningExampleResult
+ - * /add, subtract, multiply, divide7 / 23.5
**exponent (power)2 ** 38
//integer (floor) division7 // 23
%remainder (modulo)7 % 21

2.2 Lists — Python's built-in container

A list holds an ordered sequence of values in square brackets. Indexing starts at 0, not 1 — this matters constantly once you start counting nodes and matrix entries:

coords = [0.0, 2.5, 5.0, 7.5]   # x-coordinates of 4 nodes
print(coords[0])                # first entry -> 0.0
print(coords[-1])               # last entry  -> 7.5
print(len(coords))              # number of entries -> 4

2.3 Loops and conditionals

A for loop repeats a block of code once per item. range(n) generates the whole numbers 0, 1, ..., n-1:

for i in range(4):
    print("Node", i + 1, "is at x =", coords[i])

Output

Node 1 is at x = 0.0 Node 2 is at x = 2.5 Node 3 is at x = 5.0 Node 4 is at x = 7.5

if / elif / else branches on a condition. Indentation (4 spaces) — not curly braces — is what defines a block in Python:

x = 6
if x < 4:
    print("in element 1")
elif x < 8:
    print("in element 2")
else:
    print("in element 3")

2.4 Functions

A function packages a calculation you'll want to reuse. Define it once with def, call it as many times as you like:

def average(values):
    return sum(values) / len(values)

print(average(coords))   # -> 3.75
Why bother with a function? Every worked example in Lectures 1A, 2A, and 3A is really a short recipe: take these inputs, apply these steps, return this result. A Python function is exactly that recipe, except the computer runs it exactly, in a fraction of a second, as many times as you want. That's the entire pitch for the rest of this guide.

2.5 Importing libraries

Python's real power comes from importing libraries — code other people have already written. By convention, three of them are imported with short nicknames at the top of a notebook:

import numpy as np              # vectors, matrices, linear algebra
import matplotlib.pyplot as plt # plotting
import sympy as sp              # exact symbolic math

Run that cell once near the top of your notebook, and np., plt., and sp. are available in every cell below it for the rest of the session.

3. Vectors & Matrices with NumPy

Corresponding notebook cells: Section 2 (Vectors & Matrices).

Lecture 1A builds every FEM operation out of vector and matrix algebra. Plain Python lists cannot do that algebra directly — [1,2] + [3,4] glues the lists together instead of adding them. The numpy library's array type is what actually behaves like a mathematical vector or matrix.

3.1 Building a vector

import numpy as np

u = np.array([2, -1, 4])
v = np.array([0,  3, 5])

3.2 Addition, subtraction, scalar multiplication

These now work element-by-element, exactly as defined in Lecture 1A:

print(u + v)      # [ 2  2  9]
print(u - v)       # [ 2 -4 -1]
print(3 * u)        # [ 6 -3 12]

3.3 The dot product

Use np.dot, or the @ operator, for \( \mathbf{u} \cdot \mathbf{v} = \sum_i u_i v_i \):

print(np.dot(u, v))   # -1*3 + 2*0 + 4*5 -> 17
print(u @ v)           # same result, 17

3.4 Nodal coordinate & displacement vectors

The "nodal coordinate vector" built in Lecture 1A by stacking each node's x, y, z in order is just a flattened array. If pts is a list of (x, y, z) tuples for four nodes:

pts = [(1, 2, 0), (4, 2, 0), (4, 6, 0), (1, 6, 0)]
X = np.array(pts).flatten()
print(X)   # [1 2 0 4 2 0 4 6 0 1 6 0]  -- a 12-entry vector

The displacement vector d = X' - X from the same lecture is then a single subtraction, computed for all 12 entries at once instead of one at a time by hand.

3.5 Matrices

A matrix is an array of rows. NumPy reports its .shape as (rows, columns):

A = np.array([[2, 0, 1],
              [1, 3, 0],
              [0, 1, 4]])
print(A.shape)   # (3, 3)

3.6 Transpose, addition, scalar multiplication

print(A.T)        # transpose: rows and columns swapped
print(A + A.T)     # matrix addition
print(2 * A)       # scalar multiplication

3.7 Matrix multiplication — the single most important pitfall

The trap Lecture 1A warns about, in code form. A * B in NumPy multiplies element-by-element — it is not matrix multiplication and will silently give you the wrong answer. True matrix multiplication, \( [A][B] \), uses the @ operator or np.matmul: 
B = np.array([[1, 0, 0],
              [0, 1, 0],
              [0, 0, 1]])

print(A @ B)          # correct matrix product
print(np.matmul(A, B)) # identical result
# print(A * B)         # DON'T use this for matrix multiplication

As in the lecture: matrix multiplication is defined only when the number of columns of the left matrix equals the number of rows of the right matrix, and in general \( [A][B] \neq [B][A] \).

3.8 The inverse, and why you rarely compute it directly

Ainv = np.linalg.inv(A)
print(A @ Ainv)   # should be (numerically very close to) the identity matrix
Checking a candidate inverse — exactly the check performed by hand in Lecture 1A's inverse example — is just: multiply the candidate by the original matrix and see whether the product is the identity. np.allclose(A @ Ainv, np.eye(3)) does that comparison for you and returns True/False, tolerant of tiny rounding error.

3.9 Solving \([K]\{u\}=\{F\}\)

This is the equation every later lecture in this course builds toward. Given a stiffness matrix K and a force vector F, solve for the displacement vector u:

K = np.array([[ 2, -1,  0],
              [-1,  2, -1],
              [ 0, -1,  1]], dtype=float)
F = np.array([0, 0, 10], dtype=float)

u = np.linalg.solve(K, F)
print(u)
Use np.linalg.solve, not the inverse, to solve a real system. Mathematically \( \{u\} = [K]^{-1}\{F\} \), and np.linalg.inv(K) @ F gives the same answer here. But computing a full inverse is slower and less numerically stable than solving the system directly, and production FEM codes never form \([K]^{-1}\) explicitly for this reason. np.linalg.solve(K, F) is the version you should actually reach for.

Make a habit of verifying the solve, the same way you'd check a hand calculation — substitute back in and confirm you recover F:

residual = K @ u - F
print("Residual (K @ u - F):", residual)   # should be all (numerically) zero

4. Differentiation & Integration in Python

Corresponding notebook cells: Section 3 (Differentiation & Integration).

Lecture 3A draws a line between two kinds of calculus: exact calculus done symbolically with formulas, and numerical calculus done by evaluating a function at a handful of points and combining the results — the only option once a real FEM stiffness or force integral has no clean closed form. Python does both.

4.1 Exact (symbolic) differentiation with SymPy

SymPy treats x as an algebraic symbol rather than a number, so it can apply the differentiation rules from the lecture directly and return a formula:

import sympy as sp

x = sp.symbols('x')
y = -x**4 + 20*x**2 + 6*x + 5

dy_dx = sp.diff(y, x)
print(dy_dx)   # -4*x**3 + 40*x + 6

4.2 Numerical differentiation (finite differences)

When you only have a function to evaluate — not a formula — the limit definition of the derivative from the lecture, \( \frac{dy}{dx} \approx \frac{y(x+h)-y(x)}{h} \), is applied directly with a small step \(h\):

def y_func(x):
    return -x**4 + 20*x**2 + 6*x + 5

def numerical_derivative(f, x, h=1e-5):
    return (f(x + h) - f(x)) / h

print(numerical_derivative(y_func, 2.0))   # close to the exact slope at x = 2

4.3 Exact (symbolic) integration

I_exact = sp.integrate(y, (x, 0, 4))
print(I_exact, float(I_exact))   # 4348/15  ->  289.8667

4.4 The trapezoidal rule

Lecture 3A builds the composite trapezoidal rule from the areas of straight-sided trapezoids under equally spaced points. Written out by hand:

import numpy as np

a, b, n = 0, 4, 4                  # interval [0,4] split into n = 4 strips
x_pts = np.linspace(a, b, n + 1)
y_pts = y_func(x_pts)
h = (b - a) / n

I_trap = h/2 * (y_pts[0] + 2*sum(y_pts[1:-1]) + y_pts[-1])
print(I_trap)

The same result comes from a single built-in call — useful once you trust the manual version:

print(np.trapezoid(y_pts, x_pts))
A naming note. Older tutorials call this function np.trapz. NumPy renamed it to np.trapezoid; if you see np.trapz elsewhere, it's the same function under its old name.

4.5 Simpson's rule

Simpson's rule fits parabolas through pairs of strips instead of straight lines, matching the \(n=2\) Newton–Cotes formula from the lecture:

from scipy.integrate import simpson

I_simp = simpson(y_pts, x_pts)
print(I_simp)

4.6 Gaussian quadrature

Gauss points and weights for the standard interval \([-1, 1]\) come straight out of NumPy — no need to look them up in the lecture's summary table:

nodes, weights = np.polynomial.legendre.leggauss(2)   # n = 2 Gauss points
print(nodes)     # [-0.57735027  0.57735027]
print(weights)   # [1. 1.]

Mapping those points from \([-1,1]\) onto the real interval \([a,b]\) uses exactly the linear map from the lecture, \( x = \frac{b-a}{2}\xi + \frac{a+b}{2} \), with a matching Jacobian factor \(\frac{b-a}{2}\) on the weights:

def gauss_quad(f, a, b, n):
    xi, w = np.polynomial.legendre.leggauss(n)
    x_mapped = (b - a)/2 * xi + (a + b)/2
    return (b - a)/2 * np.sum(w * f(x_mapped))

print(gauss_quad(y_func, 0, 4, 2))

4.7 Accuracy vs. cost, side by side

Lecture 3A ends by comparing methods on exactly this function over \([0,4]\). Running all of them together makes the comparison concrete instead of tabulated:

print("exact:      ", float(I_exact))
print("trapezoidal:", np.trapezoid(y_pts, x_pts))
print("simpson:    ", simpson(y_pts, x_pts))
print("gauss n=2:  ", gauss_quad(y_func, 0, 4, 2))
print("gauss n=3:  ", gauss_quad(y_func, 0, 4, 3))
What you should see: the trapezoidal rule is noticeably off (it can't follow the curve's bend), Simpson's rule is much closer, and 3-point Gauss quadrature matches the exact value while 2-point Gauss does not. The reason is precise, not just qualitative: Gauss quadrature with n points is exact for any polynomial up to degree \(2n-1\). This integrand is a quartic (degree 4). For \(n=2\), \(2n-1 = 3 < 4\), so 2-point Gauss can't fully capture it — but for \(n=3\), \(2n-1 = 5 \ge 4\), so it's exact, reproducing the point in the lecture where accuracy stops improving with more points because the answer is already exact.

5. Interpolation & Shape Functions in Python

Corresponding notebook cells: Section 4 (Interpolation & Shape Functions).

Lecture 2A already sprinkles in short Python snippets alongside the hand calculations — this section collects that same style into one place and carries it through every shape-function family in the lecture, from linear hat functions to the bilinear rectangle.

5.1 Linear interpolation, in normalized coordinates

Recall the two linear shape functions defined on \(\xi \in [-1,1]\): \(N_k(\xi) = \frac{1-\xi}{2}\), \(N_{k+1}(\xi) = \frac{1+\xi}{2}\). Written as Python functions, they take a natural coordinate and return a blend weight — nothing about the segment's real-world length or position appears anywhere:

def xi_from_x(x, xk, xk1):
    return (2*x - xk - xk1) / (xk1 - xk)

def N_linear(xi):
    return (1 - xi) / 2, (1 + xi) / 2   # N_k, N_k+1

xk, xk1 = 0.2, 0.6
yk, yk1 = 2, -1

xi = xi_from_x(0.5, xk, xk1)
Nk, Nk1 = N_linear(xi)
y = Nk * yk + Nk1 * yk1
print(y)   # -0.25, matching the lecture's worked example

5.2 Quadratic shape functions

The three-node quadratic bases from the lecture, with nodes at \(\xi=-1,0,1\):

def N_quad(xi):
    Nm1 = xi * (xi - 1) / 2
    N0  = 1 - xi**2
    Np1 = xi * (xi + 1) / 2
    return Nm1, N0, Np1

F_nodes = [2, -1, 3]
Nm1, N0, Np1 = N_quad(0.0)
F = Nm1*F_nodes[0] + N0*F_nodes[1] + Np1*F_nodes[2]
print(F)   # -1, reproducing the middle nodal value exactly

5.3 The general Lagrange basis, for any order \(n\)

Rather than deriving a new formula every time the element order changes, the lecture's general Lagrange formula \( L_{k,n}(x) = \prod_{j \neq k} \frac{x-x_j}{x_k-x_j} \) is written once, for any number of nodes:

def lagrange_basis(k, nodes, x):
    """L_{k,n}(x): 1 at nodes[k], 0 at every other node."""
    n = len(nodes)
    L = 1.0
    for j in range(n):
        if j != k:
            L *= (x - nodes[j]) / (nodes[k] - nodes[j])
    return L

def lagrange_interp(nodes, values, x):
    return sum(lagrange_basis(k, nodes, x) * values[k]
               for k in range(len(nodes)))

nodes  = [0.2, 0.4, 0.6]
values = [2, 0, -1]
print(lagrange_interp(nodes, values, 0.5))
The trap this guards against. Lecture 2A flags that forgetting to skip \(j=k\) in the product silently breaks the "1 at its own node" property. Writing the formula as a loop with an explicit if j != k makes that condition impossible to forget, unlike re-deriving the product by hand for each new element order.

5.4 Bilinear interpolation on a rectangle

The 2D bilinear element is the tensor product of two 1D linear bases, one in \(\xi\) and one in \(\eta\):

def bilinear(xi, eta, f11, f21, f12, f22):
    N11 = (1 - xi) * (1 - eta) / 4
    N21 = (1 + xi) * (1 - eta) / 4
    N12 = (1 - xi) * (1 + eta) / 4
    N22 = (1 + xi) * (1 + eta) / 4
    return N11*f11 + N21*f21 + N12*f12 + N22*f22

# corner values f(x1,y1), f(x2,y1), f(x1,y2), f(x2,y2)
value_at_center = bilinear(0, 0, 10, 14, 12, 18)
print(value_at_center)   # average of the 4 corners at the element center

5.5 Seeing the shape functions, not just evaluating them

A plot makes the defining property of a shape function ("1 at its own node, 0 at every other node") visible instead of abstract — genuinely easier to trust after watching the curve than after reading the formula:

import numpy as np
import matplotlib.pyplot as plt

xi_vals = np.linspace(-1, 1, 200)
Nk_vals  = (1 - xi_vals) / 2
Nk1_vals = (1 + xi_vals) / 2

plt.plot(xi_vals, Nk_vals,  label="N_k(\u03be)")
plt.plot(xi_vals, Nk1_vals, label="N_k+1(\u03be)")
plt.xlabel("\u03be")
plt.ylabel("shape function value")
plt.legend()
plt.grid(True)
plt.show()

Every plot in this guide's companion notebook follows this same three-line pattern: build an array of x-values with np.linspace, compute the matching y-values, then plt.plot(...).
